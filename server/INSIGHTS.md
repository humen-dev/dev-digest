## What Works
- 2026-09-27 — Seed fixtures are insert-once: the demo PR block in `server/src/db/seed.ts:277` is guarded by `if (!pr)`, so re-running `pnpm db:seed` on an already-seeded dev DB does NOT pick up changed `pr_files` rows or patches. To verify a seed change, start a throwaway Postgres container on a spare port, point `DATABASE_URL` at it, run `pnpm db:migrate && pnpm db:seed`, hit the API, then `docker rm -f` it — never touch `devdigest-postgres` and never `docker compose down -v` (wipes `devdigest_pgdata`). The Smart Diff seed (PR #482 with all five roles) was verified this way.

## What Doesn't Work
- 2026-09-29 — NEVER resolve a single-segment Python import (`celery`, `logging`, `types`) by matching the suffix of any local file path. The standard Django+Celery layout has `proj/celery.py`, so `from celery import shared_task` in every `tasks.py` bound to the local file. That gave false `file_edges` and an inflated blast `indirect` set. Python 3 absolute imports only resolve from a source root. ALWAYS keep the suffix fallback for multi-segment names with a unique match only, and use a lookup table built once per index, not a scan over every file for each import (`server/src/adapters/python/imports.ts:85`, `:93`).
- 2026-09-29 — NEVER widen `SUPPORTED_EXT` (`server/src/modules/repo-intel/constants.ts:14`) to add a language to the indexer. It is not just the walk filter. `adapters/astgrep/index.ts:55` (`parseChangedFiles`) and the phantom-API gate at `repo-intel/service.ts:590` also read it and would feed the new files into JS/TS-only ast-grep parsing, and `depgraph/index.ts` feeds dependency-cruiser from the same set. ALWAYS add a separate extension set (the Python plan uses `PYTHON_EXT` + `INDEXED_EXT` for walk/incremental, `docs/plans/repo-intel-python.md` Decision 4) and route per language.
- 2026-09-29 — NEVER return `path.relative(...)` as a repo path on the indexer side without converting to POSIX: on Windows it yields `src\lib\money.ts`, while the indexer's file list is `src/lib/money.ts`. As a result `DepCruiseGraph.buildEdges` silently returned `[]` for every repo: no `file_edges`, no `decl_file`, a flat rank, and **Blast Radius showed 0 callers** even though `references` rows existed. Symptom: `file_edges` empty while `references.decl_file` is NULL. Fixed with `.split(sep).join('/')` in `toRel` (`server/src/adapters/depgraph/index.ts`), pinned by `server/test/depgraph.test.ts`. ALWAYS bump `INDEXER_VERSION` (`server/src/modules/repo-intel/constants.ts`) for such fixes: a resync with an unchanged SHA exits early unless the version differs, so old indexes are never rebuilt otherwise.
- 2026-09-29 — NEVER trust `repoIntel.getBlastRadius`'s own `degraded`/`reason` for index health: the ripgrep fallback ALWAYS tags `reason: 'no_data'` even when `REPO_INTEL_ENABLED=false` (`server/src/modules/repo-intel/service.ts:224`, `:303`), and the persistent path returns `degraded: false` even for a `partial` index (`:385-391`) — so `flag_off` / `index_partial` / `index_failed` never come out of the facade. It also slices callers to `MAX_CALLERS_PER_SYMBOL` over the WHOLE PR, not per symbol (`:387`), despite the constant's doc. ALWAYS refine with the config flag + `getIndexState` (never throws) and re-cap per symbol yourself, as `server/src/modules/blast/domain/degradation.ts` and `build-blast-radius.ts` do.
- 2026-09-27 — NEVER flip an agent run to a terminal status before its trace is persisted: clients (and `reviews.it.test.ts`) poll the run status and fetch `GET /runs/:id/trace` as soon as they see `done`/`failed`, so status-then-trace yields an intermittent 404. It was latent until the intent pre-work step widened the gap, after which the "imports a file…" IT failed on nearly every run. ALWAYS `saveRunTrace` first, then `completeAgentRun` — in the success path, the failure/cancel catch and `failAll` (`server/src/modules/reviews/run-executor.ts:81-84`, `:320-323`, `:349-352`). If that test flakes with `expected 404 to be 200`, check this order before blaming timing.
- 2026-09-27 — NEVER write a glob literal containing `**/` (e.g. `**/specs/**`) inside a `/** … */` JSDoc block: the `*/` in `**/` closes the comment early, the rest of the sentence is parsed as code and `tsc` reports a baffling TS2304 ("Cannot find name 'specs'") far from the real cause. Refer to the named constant instead of spelling the glob in prose — the intent module documents `PLAN_SPEC_GLOBS` (`server/src/modules/intent/constants.ts:19`) by name in `server/src/modules/intent/domain/references.ts:52`. Plain string literals in code are fine; only block comments are affected.
- 2026-09-21 — A route test that only overrides the repository port is NOT DB-free: `getContext()` calls `container.auth.currentWorkspace(req)` (`server/src/modules/_shared/context.ts:20`) and the default auth is `new LocalNoAuthProvider(db)` (`server/src/platform/container.ts:84`), which reads the default workspace from Postgres — so the test silently needs Docker/a DB. ALWAYS also pass `overrides: { auth: new MockAuthProvider() }` (`server/src/adapters/mocks.ts:314`) when testing a route without a DB.

## Codebase Patterns
- 2026-09-29 — Blast Radius endpoint and cron attribution is **per file, not per function**. `file_facts` stores the endpoints and crons of a whole file (`adapters/codeindex/extract.ts` regexes per line), and `buildBlastRadius` unions the facts of each caller *file*. So when one route file holds handlers for two symbols (`invoices.ts` has `createInvoice`→`formatMoney` and `previewTax`→`roundCents`), both symbols list both endpoints. Treat that as expected: don't "fix" it in the blast mapper. Real per-handler attribution needs repo-intel to store which enclosing symbol registers each route. Demo evidence: `humen-dev/blast-radius-demo` PR #1.
- 2026-09-27 — `container.ts` cannot import ANY runtime export from a module file that itself `import type`s `Container`: e.g. `loadDiff` from `server/src/modules/reviews/diff-loader.ts` (which takes the whole `Container`) closes a `container.ts → diff-loader.ts → container.ts` cycle and depcruise `no-circular` fails, even though the back-edge is type-only. The intent layer therefore re-implements diff loading inline in the composition root over the adapter-level `parseUnifiedDiff` (`server/src/platform/container.ts:158-186`) — a known duplication. The real fix is to give such helpers narrow structural deps instead of `Container`, after which the container can import them; until then, check depcruise before wiring a module helper into `container.ts`.
- 2026-09-27 — A module's `ports.ts` may not import an ADAPTER interface either (not just ORM row types, see 2026-09-22 below): `import type { UrlFetcher } from '../../adapters/url-fetcher/index.js'` trips depcruise `domain-no-outer-layers`. Declare the minimal structural shape locally instead — `IntentUrlFetch` (`server/src/modules/intent/ports.ts:107`) — and wire the real adapter in `container.ts` (`urls: this.urlFetcher`); `HttpUrlFetcher` satisfies it structurally, so no cast or wrapper is needed.
- 2026-09-24 — Skill prompt-injection blocking is COMPUTED, not stored: `injection_detected` is derived from `body` on every read (`server/src/modules/skills/mappers.ts`), so there is no column/migration and legacy rows are covered for free. Enforcement is at two points that must both stay: `SkillsService.blockIfInjected` force-disables on create/update/restore via a body-less `repo.update` (no version bump; `server/src/modules/skills/service.ts`), and `renderSkillBlocks` drops any injected skill even if a legacy row is still `enabled` (`server/src/modules/reviews/helpers.ts:114`). The detector lives in `server/src/modules/_shared/injection.ts`, NOT under `skills/`, because `reviews` needs it and `no-cross-module-internals` forbids importing another module's `domain/` — only `_shared/` and a module's `index|ports|types.ts` are allowed (`server/.dependency-cruiser.cjs:150-158`). NEVER write a broad "always/never … approve|flag" pattern: it false-positives on legitimate rules like "Never approve a PR with failing tests" — keep patterns specific (`score: 100`, `approve all PRs`, `never flag security`) and keep the fixtures test (`server/test/skill-injection.test.ts`) that runs every `docs/skill-fixtures/*.md` through the detector expecting zero hits. The `injection_detected` field was added to BOTH vendored `knowledge.ts` copies by hand — there is no source package in this repo.
- 2026-09-24 — Any server-side fetch of a USER-SUPPLIED URL (skills "Import from URL") goes through the `UrlFetcher` adapter, never a bare `fetch` in a service: `HttpUrlFetcher` (`server/src/adapters/url-fetcher/index.ts:71`) allows only http(s), resolves the host and rejects if ANY returned address is private/loopback/link-local (`isPrivateAddress`, incl. `169.254.169.254` and `::ffff:` mapped v4), follows redirects MANUALLY (`redirect: 'manual'`, ≤3 hops) re-validating every hop — with automatic redirects a public URL can 302 to `127.0.0.1` — and caps size (streamed, not just `content-length`) and time. It is wired as a `Container.urlFetcher` getter with a `ContainerOverrides.urlFetcher` seam (`server/src/platform/container.ts`), so tests stub it instead of hitting the network; `SkillsService` receives it as a 3rd constructor arg and is built in TWO places (`container.ts` `services.skills` and `modules/skills/routes.ts:78`) — change both. KNOWN GAP: validation (`lookup`) and the actual `fetch` resolve DNS separately, so a DNS-rebinding host can still slip through; closing it needs a pinned-IP `undici` dispatcher. Unit cover: `server/test/url-fetcher.test.ts`.
- 2026-09-23 — When a service needs a capability another module owns, the port's IMPLEMENTATION can live inline in `container.ts` instead of reaching for that module's service class. `ConventionsService` needed "append this skill to an agent", and `AgentsService` would have fit exactly — but it takes the whole `Container` (`server/src/modules/agents/service.ts:54`), so importing it into the composition root adds a runtime edge into a module that type-imports the container back, and the depcruise baseline is frozen at 30 known violations that must never grow. The narrow port is declared boolean-shaped so it needs no DTO (`AgentLinkerPort.linkSkill(...): Promise<boolean>`, `server/src/modules/conventions/ports.ts:112`) and is satisfied by a 5-line object literal over `this.agentsRepo` in `server/src/platform/container.ts:140` — the service still throws its own `NotFoundError` on `false`. Prefer this over a cross-module service import whenever the borrowed behaviour is one or two repository calls.
- 2026-09-23 — An author-supplied note that describes a *version* has nowhere to live unless that request actually creates a version. `PUT /skills/:id` only appends a `skill_versions` snapshot when `body` changes (`server/src/modules/skills/repository.ts` `update()`), so `version_message` on a name-only patch must be **dropped, not written onto the existing latest version** — back-writing it would retroactively relabel a snapshot the caller never saw. The drop is implicit (the note is only passed to `insertVersionSnapshot`, which is only reached on a body change), so it needs an explicit test to stay true: `server/test/skills-crud.it.test.ts` asserts both "message lands on the new version" and "message on a no-bump patch leaves v1 null". Same reasoning makes a restore record `message: null` — it copies an old body rather than authoring a new one.
- 2026-09-22 — A `ports.ts` interface must NOT reference row types imported from its own `repository.ts` (`typeof t.<table>.$inferSelect`) — that's both `domain-no-outer-layers` (port depending on the ORM-touching infrastructure file) and a `no-circular` (since `repository.ts` imports the port it implements). It also must NOT define those row types itself via `import type * as t from '../../db/schema.js'` — depcruise flags that too (`orm-only-in-repositories`, `domain-no-outer-layers`): only `repository*` and a module's `mappers.ts` may touch `db/schema`/`drizzle-orm` (`.claude/skills/onion-architecture/references/enforcement.md:30-32`). The fix (`server/src/modules/skills/ports.ts`): declare row shapes in `ports.ts` as PLAIN hand-written interfaces (field names/types copied from the schema, e.g. `evidenceFiles: string[] | null`, `createdAt: Date`) with zero ORM import; `repository.ts` then imports those same names FROM `ports.ts` for its method signatures — Drizzle's actual `.select()`/`.returning()` results are structurally assignable to the plain interface, so no mapping/cast is needed at the boundary. `skills` was the first module in this repo to actually use the narrow-port pattern (`repo-intel`, the only other module depcruise was written against, doesn't have a `ports.ts`), so this had never been exercised before.
- 2026-09-22 — Reaching into another module's `repository.ts` for a type (e.g. `import type { LinkedSkillRow } from '../agents/repository.js'` from `reviews/helpers.ts`) trips `no-cross-module-internals` even though the value crossing the boundary at runtime already goes through `container.agentsRepo` (allowed). Fix: declare the minimal structural shape the consuming function actually needs locally (`reviews/helpers.ts`'s `SkillLinkForPrompt`) instead of importing the other module's full row type — TypeScript's structural typing accepts the wider concrete type from the other module without an import or adapter, and the two modules stay decoupled at the type level too.
- 2026-09-22 — `server/.dependency-cruiser.cjs` does NOT exist on `main` (nor on any fresh `feature-L0N` branch cut from it) even though `AGENTS.md`'s onion-architecture checklist references `pnpm exec depcruise src --config .dependency-cruiser.cjs --ignore-known`. It was added on `422e203` then removed again by `c6af1e4 revert: restore main to the starter state, homework belongs in forks` — depcruise enforcement is itself lesson/homework content, not part of the starter. On a branch without the config, verify onion boundaries by construction instead (module's `service.ts` importing only its own `ports.ts` + narrow adapters, never `platform/container.ts`) and say so explicitly in any report rather than silently skipping the check or trying to regenerate a baseline file that was never meant to be on this branch.
- 2026-09-22 — When seeding a PR fixture for a demo repo (e.g. `acme/payments-api`, no real git clone) the reviewer's diff loader (`server/src/modules/reviews/diff-loader.ts:33` `diffFromPrFiles`) falls back to reconstructing a `UnifiedDiff` from `pr_files.patch` via `parseUnifiedDiff` — so each seeded `pr_files` row's `patch` column must hold a REAL unified-diff hunk body (`@@ -a,b +c,d @@` + context/added/removed lines), not just additions/deletions counts or a description. A patch with only metadata parses to zero hunks and the review sees an empty diff. Verify with the actual `parseUnifiedDiff` (`server/src/adapters/git/diff-parser.ts`) against the assembled `diff --git a/<path> b/<path>` + `--- a/<path>` + `+++ b/<path>` + `f.patch` text before trusting new-side line numbers in any skill/finding examples that cite `file:line` — an off-by-one here silently points findings at the wrong line.
- 2026-09-19 — The PR list (`GET /repos/:id/pulls`) enriches each `PrMeta` with fields computed on READ (no denormalization): latest-review `score`, `cost_usd`, and `findings` — each a single `IN (...prIds)` query + JS grouping (`server/src/modules/pulls/routes.ts:114-190`). `findings` aggregates across **all** `kind='review'` reviews of a PR (matches the detail page), mapped to the `Finding` contract via `findingRowToDto` (`server/src/modules/reviews/helpers.ts:34`). **SUPERSEDES the 2026-09-18 cost note below:** PR-list `cost_usd` is now the **SUM** of every priced run for the PR (its total spend), not the latest priced run (`server/src/modules/pulls/routes.ts:132-155`).
- 2026-09-18 — Only OpenRouter reports a REAL per-call USD cost (`usage.cost`); the `openai`/`anthropic` adapters always return `estimateCost(...)` (`server/src/adapters/llm/openai.ts:84`). Persist real cost only: `run-executor` writes `ReviewOutcome.apiCostUsd` into `agent_runs.cost_usd` (null for openai/anthropic/unpriced runs), never the estimate (`server/src/modules/reviews/run-executor.ts`). PR-list COST is the latest run whose `cost_usd` is non-null, so a just-failed newest run doesn't blank the column (`server/src/modules/pulls/routes.ts`).

## Tool & Library Notes
- 2026-09-21 — **Repo-wide, learned while running server checks from a scratch worktree:** `git rev-parse --git-path info/exclude` inside a LINKED worktree resolves to the **shared** repository (`.git/info/exclude`), not to anything worktree-local — so a "temporary, worktree-only" exclude silently applies to the main checkout too. Appending `.claude/` there hid the entire directory from `git status` in the primary tree, and new files under it would never have been committed. NEVER write worktree-scoped ignores through `--git-path info/exclude`; use `git -c core.excludesFile=<tmp>` or just delete the probe files afterwards, and re-check `git status` in the main worktree before trusting it.
- 2026-09-21 — Node 22 on Windows refuses `spawnSync('pnpm.cmd', args, { shell: false })` with **`EINVAL`** — the fix for CVE-2024-27980 blocks spawning `.cmd`/`.bat` shims without a shell. Anything that scripts `pnpm typecheck` / `pnpm exec vitest` / `pnpm exec depcruise` from Node reports "could not start" instead of running, and a naive wrapper reads that as a pass. ALWAYS pass `shell: process.platform === 'win32'` and leave the binary name bare (`pnpm`, not `pnpm.cmd`): cmd.exe does not expand `*`, so glob arguments such as `--exclude **/*.it.test.ts` survive, while POSIX keeps `shell: false` (`.claude/skills/pr-self-review/scripts/checks.mjs:14`).
- 2026-09-21 — **SUPERSEDES the `skip-worktree` entry below:** `server/package.json` is NOT skip-worktree in this clone — `git ls-files -v server/package.json` reports `H` (plain), and no tracked file in the repo carries `S`/`h`. skip-worktree is a **local index bit, never committed**, so it can be true on the machine that wrote that note and false everywhere else; the claim in `.github/workflows/server-unit.yml:104` is a stale comment, not a fact about the repo. ALWAYS verify with `git ls-files -v <path>` in the current clone before assuming a script you add won't be committed — a script added to `server/package.json` here WILL be committed. Inlining the CI commands is still the right call (it survives either state), but for reproducibility, not because the file is pinned.
- 2026-09-21 — **QUALIFIES the pnpm-path entry below:** the resolved path of an npm package differs by environment (Windows dev: `node_modules/.pnpm/drizzle-orm@0.38.4_postgres@3.4.9/node_modules/drizzle-orm/index.d.ts`; Linux CI: `node_modules/drizzle-orm/index.d.ts`), and the depcruise baseline is keyed on the resolved `to` path — so 5 baselined `drizzle-orm` entries looked "new" in CI and failed `server unit` while passing locally. ALWAYS keep `preserveSymlinks: true` (`server/.dependency-cruiser.cjs:174`) so paths are `node_modules/<pkg>/…` everywhere, and verify a baseline change on CI, not only on your machine.
- 2026-09-21 — dependency-cruiser resolves pnpm packages to `node_modules/.pnpm/<pkg>@<ver>/node_modules/<pkg>/…`, so a rule written as `^node_modules/drizzle-orm` NEVER matches and fails silently (a dead rule that reports green). Match npm packages with `(^|/)node_modules/<pkg>(/|$)` — the `npm()` helper in `server/.dependency-cruiser.cjs:20`. ALWAYS prove a new rule with a throw-away probe file that violates it before trusting a green run.
- 2026-09-21 — `server/package.json` is `skip-worktree` in this repo (the workflows already say so: `.github/workflows/server-unit.yml:104`), so a script added to it (e.g. an `arch:check`) is NOT committed and CI never sees it. NEVER rely on new package scripts for CI; call the tool inline like the architecture step does (`.github/workflows/server-unit.yml:72-73`, `pnpm exec depcruise src --config .dependency-cruiser.cjs --ignore-known`).

## Recurring Errors & Fixes
- 2026-09-27 — Reading a regex match by **positional index** silently breaks when an alternation contains a nested optional group: `ISSUE_REF_RE` had `fix(e[sd])?`, so `m[2]` was `'es'`/`undefined`, `Number(...)` gave `NaN`, the `Number.isFinite` guard dropped it and every "Fixes #N" vanished with no error — typecheck and existing tests stayed green. ALWAYS make helper groups non-capturing (`(?:…)`) and read the value from a **named group** (`#(?<num>\d+)` → `m.groups?.num`), as in `server/src/modules/intent/constants.ts:22` + `domain/references.ts:122`; pin it with a table test (`server/test/intent-references.test.ts`).
- 2026-09-18 — Deriving a parent dir with `full.lastIndexOf('/')` breaks on Windows: `path.join` normalizes separators to `\`, so there is no `/` → `slash = -1` → `mkdir` skipped → `writeFile` fails ENOENT (6 tests). ALWAYS use `dirname()` for the parent dir, never a hardcoded `/` scan (`server/test/indexer-pipeline.test.ts:140`).

## Open Questions
- 2026-09-29 — RESOLVED (supersedes the entry below): incremental reindex now patches Python facts over `allPyFiles ∪ changed .py`, so deleted files are cleared too. It patches only when a `.py` changed, and a truncated pass keeps the existing facts. The Python pass still runs on JS-only commits, because `repository.replaceEdges` rewrites the whole edge set and would otherwise drop the Python edges (`server/src/modules/repo-intel/pipeline/incremental.ts:221`, `:233`, `:260-266`, `:272`). Avoiding that pass needs a per-file edge replace on the repository port.
- 2026-09-29 — Incremental Python reindex never clears the facts of the LAST deleted `.py` file. The Python fact patch runs only when `allPyFiles.length > 0` (`server/src/modules/repo-intel/pipeline/incremental.ts:224`, `:240`). So if a commit removes every `.py` file, their old `file_facts` rows (endpoints/crons) stay behind and still show up in Blast Radius until a full reindex (`INDEXER_VERSION` bump or a fresh clone). Open: patch with an empty row set when the tree had Python files before, or delete facts for removed paths generically.
