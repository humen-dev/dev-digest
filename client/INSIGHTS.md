## What Works
- 2026-09-23 — SUPERSEDES the 2026-09-22 "no syntax highlighting" note below: the transparent-textarea-over-`<pre>` overlay was built and does hold up, on three conditions that are the whole trick. (1) Both text layers are built from the same named metric constants — font-family/size/line-height/padding/tab-size — never from their own literals (`client/src/app/skills/[id]/_components/SkillEditor/_components/ConfigTab/_components/SkillBodyEditor/styles.ts:21`); one divergent metric offsets the caret from its colours. (2) `white-space: pre` on both layers, scrolling sideways instead of soft-wrapping — this is also what makes the one-row-per-line gutter correct, since a soft-wrapped logical line would occupy two visual rows and silently desync the numbers. (3) The tokenizer is LOSSLESS, and that is the property to unit-test (`…/SkillBodyEditor/helpers.test.ts:24`): joining a line's token texts must rebuild the line byte for byte, so a dropped/added character can never shift the glyphs after it. jsdom still can't verify alignment, but with (1)-(3) the only thing left to check by eye is scroll sync.

## What Doesn't Work
- 2026-09-20 — The `react-best-practices` skill says to use "the project's `useApiQuery`/`useApiMutation` core hooks" (`.claude/skills/react-best-practices/SKILL.md:111`), but no such hooks exist in the client — following it yields imports that don't resolve. ALWAYS follow the code: domain hooks in `src/lib/hooks/<domain>.ts` call `useQuery`/`useMutation` with `api.get/post/put` and own the queryKey + invalidation (`client/src/lib/hooks/agents.ts:8`, `client/src/lib/hooks/agents.ts:34`).
- 2026-09-18 — A fixed-decimal cost format (e.g. 4 dp under a cent) FLATTENS real cheap-model costs: a deepseek/OpenRouter review run costs ~$0.00004, which 4 dp renders as "$0.0000" (looks free) and collapses distinct tiny values ($0.000175 vs $0.000248) onto one string. Use 2 significant figures below $0.01 (`toPrecision(2)`), keep 3 dp at/above $0.01 (`client/src/lib/format-cost.ts:12`). Only surfaced against LIVE seeded costs in the browser — the design mock values ($0.0013+) hid it.

## Codebase Patterns
- 2026-09-23 — Changing what a CLICK does in a list view silently breaks the e2e flows, and nothing in the client's own gate catches it: `client` typecheck + vitest stay green while `e2e/specs/08-skills.flow.json` and `09-skill-versions.flow.json` still do `find text "<skill name>" click` followed by `wait --url /skills/`, which now never resolves because the card opens a preview panel instead of navigating. The flows are hand-written JSON assertions over literal on-screen strings, so they also break on a reworded message key. ALWAYS `rg` the clicked/asserted string in `e2e/specs/` before changing an interaction or a translation on `/skills`, `/agents`, `/repos/:id/conventions` and thread the new step in (`find text "Open editor" click`) rather than discovering it in the hermetic run.
- 2026-09-23 — `@devdigest/shared` is vendored TWICE (`client/src/vendor/shared/` and `server/src/vendor/shared/`) and the two copies have **already drifted** — the server copy carries `AgentVersion` contracts the client copy lacks. So a contract change like adding `message` to `SkillVersion` must be applied by hand to BOTH files or the halves disagree silently: nothing cross-checks them, and each package typechecks happily against its own copy (the client would just never see the new field). Diffing the two to "resync" them is the wrong instinct — the drift is pre-existing and out of scope; edit only the contract block your change touches, identically in both. Same "the vendored copy *is* the source" caveat as the `vendor/ui` entry below.

- 2026-09-23 — `@devdigest/ui`'s `<Markdown>` only overrode `p`/`strong`/`code`/`a`, so every BLOCK element it emitted (headings, `ul`/`ol`, blockquote, tables) rendered as flat prose — Tailwind's preflight plus `h1..h4, p { margin: 0 }` in `client/src/vendor/ui/styles.css:205` strips heading scale and list markers, and nothing put them back. This silently degraded every consumer, not just the skill Preview tab (finding rationales lost their bullets too: `FindingCard.tsx:80`, `CommentCard.tsx:31`). Block typography now lives in a `.dd-md` CSS block (`client/src/vendor/ui/styles.css:220`) because `::marker` and `:first-child` cannot be expressed as inline styles, while inline spans stay in the `components` map. ALWAYS add rendered-markdown styling in that CSS block — and note inline styles WIN over it, which is why a fenced block's `<code>` has to drop the inline pill in `Markdown.tsx` rather than be reset from CSS.
- 2026-09-23 — Skills Lab index routes (`/agents`, `/skills`) are full-page card grids that navigate only on click; ONLY the repo root (`/`) auto-redirects to its first item. `/skills` originally shipped as `router.replace('/skills/' + skills[0].id)` deliberately mirroring that root redirect, and it was reverted because it hides the list the user navigated for (the skeleton branch guarding the redirect also meant the card list was literally unreachable at `/skills`). The index is now a thin route over `_components/SkillsListView`, modeled 1:1 on `client/src/app/agents/_components/AgentsListView/AgentsListView.tsx:17` (same `page`/`header`/`grid` styles and `CARD_GRID_COLS`). NEVER reintroduce an auto-select-first-item redirect on a Skills Lab index — the 280px `SkillsListColumn` rail on `/skills/[id]` is the *detail* affordance, not the list (`client/src/app/skills/page.tsx:1`, `client/src/app/skills/[id]/page.tsx:56`).
- 2026-09-22 — `client/src/vendor/ui/nav.ts` (WORKSPACE items + `SHORTCUTS`) was edited
  directly to add the `skills` nav entry, even though `src/vendor/*` is normally
  "vendored — edit at the source package, not here" (client/CLAUDE.md). There is no
  upstream `@devdigest/ui` package in this repo to edit instead — the vendored copy
  *is* the source — so this is a deliberate, documented exception, not drift. Next
  time a nav item needs adding, edit `nav.ts` in place; don't go looking for an
  upstream repo that doesn't exist.
- 2026-09-20 — NEVER "fix" the layout by hoisting `AppShell` into a layout or by adding a `features/` layer — both are deliberate owner decisions, not drift. Each route view renders `<AppShell crumb=…>` itself because the page owns its breadcrumbs and a layout can't see page data (`client/src/components/app-shell/AppShell.tsx:10` takes `crumb`; call sites e.g. `client/src/app/repos/[repoId]/pulls/page.tsx:66`). Accepted trade-off: the shell remounts on navigation (this contradicts the generic Next.js "persistent chrome in a layout" advice). New route views follow the same pattern; structure stays route `_components` + `src/components` + `src/lib`. Rationale and the rest of the placement rules: `.claude/skills/frontend-ui-architecture/references/devdigest-client-mapping.md`.
- 2026-09-19 — A hover popover anchored inside the PR-list table (`client/src/app/repos/[repoId]/pulls/styles.ts:91` `tableCard` has `overflow:hidden`) gets CLIPPED if positioned `absolute` within a row — worst on the last row. Render it in a **portal to `document.body`** with `position:fixed` computed from the trigger's `getBoundingClientRect()`, and clamp `maxHeight` to `innerHeight - top - 12` so it never overflows the viewport (no flip logic needed). See `client/src/app/repos/[repoId]/pulls/_components/FindingsHoverCard/FindingsHoverCard.tsx:73`. There is no Tooltip/Popover primitive in `@devdigest/ui` — only a click `Dropdown` (`vendor/ui/kit`), so hover popovers are hand-rolled; reuse `FindingsHoverCard` + `FindingsPreviewList` (shared by the list cell and the Agent-runs timeline).

## Tool & Library Notes
- 2026-09-23 — RTL `getByDisplayValue` cannot locate a MULTI-LINE `<textarea>` by its exact value (it normalizes whitespace, so a body like `"# a\n\n## b"` never matches) — the 3 `CreateSkillFromConventionsModal` tests failed with "Unable to find an element with the display value". Query the element (`document.querySelector("textarea")`) and assert on `.value`; single-line inputs are fine (`client/src/app/repos/[repoId]/conventions/_components/CreateSkillFromConventionsModal/CreateSkillFromConventionsModal.test.tsx`, `bodyBox`).
- 2026-09-23 — next-intl's `t.rich` takes tag renderers and ICU values from ONE object, so a tag and a placeholder can never share a name: a message written as `in <repo>{repo}</repo>` cannot be served by `{ repo: chunks => <span>…</span>, repo: repoName }` — the tag renderer wins and the value is lost. Rename the placeholder (`<repo>{repoName}</repo>`) rather than the tag, since the tag name is what reads as markup in the message (`client/messages/en/conventions.json:74`, `client/src/app/repos/[repoId]/conventions/_components/CreateSkillFromConventionsModal/CreateSkillFromConventionsModal.tsx:95`). This is the client's first `t.rich` call site — everything else uses plain `t()`, so there was no precedent to copy.
- 2026-09-22 — `SkillBodyEditor` (`client/src/app/skills/[id]/_components/SkillEditor/_components/ConfigTab/_components/SkillBodyEditor/SkillBodyEditor.tsx`)
  ships as a plain monospace `<textarea>` + a synced line-number gutter, with NO
  markdown syntax highlighting. The plan explicitly allowed falling back from a
  transparent-textarea-over-`<pre>` regex-highlight overlay if it proved fragile
  (scroll/wrap desync) rather than pulling in CodeMirror for one field — we took
  that fallback up front instead of building the overlay first, since jsdom
  doesn't lay out text (no real `scrollHeight`/wrapping), so the one thing that
  would actually validate overlay alignment (visual scroll sync) can't be unit
  tested anyway. If highlighting is wanted later, prototype it manually in the
  browser before trusting any test to catch desync.

## Recurring Errors & Fixes
- 2026-09-23 — `tsc --noEmit` fails with `TS2742: The inferred type of 's' cannot be named without a reference to '.pnpm/csstype@…/node_modules/csstype'` as soon as a `styles.ts` SPREADS a `CSSProperties`-typed object into an entry of the exported `s` (`{ ...layer, overflow: "hidden" } satisfies CSSProperties`) — pnpm's isolated `node_modules` makes csstype's property types unnameable from the declaration. The repo's usual `satisfies CSSProperties` + `as const` is only safe on plain literals, whose inferred types stay primitive. Fix: hoist the shared base to a `const x: CSSProperties = {…}` and annotate each spread-built entry the same way, then reference them by name in `s` — the annotation is `React.CSSProperties`, which IS nameable. Keep raw numbers/strings (not `base.fontSize`) for metrics reused in non-spread entries, or they drag the same csstype types in (`client/src/app/skills/[id]/_components/SkillEditor/_components/ConfigTab/_components/SkillBodyEditor/styles.ts:21`).
